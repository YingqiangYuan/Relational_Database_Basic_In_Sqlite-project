# 怎么吃透一个小型学习 repo（以关系数据库为例）

## 这门课学什么？

先把调子定好：**这门课教的不是"关系数据库"，是"怎么把一个小型学习 repo 彻底吃透"的方法论**。关系数据库只是这门课的载体——它足够简单，文科生只要走完之前那套"用 AI 学习"的前置课，也能跟得上；但它又足够完整，能撑起整套方法。

### 大项目 vs 小项目

你在做事和提升自己的过程中，会接到两种项目：

- **大项目** —— 复杂、要交付一个完整结果的东西。比如"做一个内部工具"、"上线一个数据管道"。这种项目里包含很多小知识点。
- **小项目** —— 你做大项目时，碰到一个不熟的技能/知识点/工具，把它**单独拎出来**做一个最小可运行的例子，专门把它学透。这种就是"小项目"。

本课程是后者的范例。**真正的产品不是关系数据库的代码——是你拿到一个像这样的小 repo 之后，应该用什么动作把它彻底吃透**。

### 学完你能带走什么

你不是学会了"SQLAlchemy + SQLite"。你学会的是一套方法论——任何类似的小 repo 来了，你都能用这五个动作走完：

- **吃透**（absorb）—— 项目里有的东西，逐个搞清楚 *是什么、为什么这么写*
- **拔高**（elevate）—— 项目里没有但应该有的方向，以及要做这些升级你需要先学什么
- **检验**（quiz）—— 用 AI 出题逼自己，区分"以为自己懂"和"真懂"
- **应对**（interview）—— 模拟别人来考你，连同那些会但不熟、相关但还不会的问题一起练
- **展示**（demo）—— 把这个项目讲给不同受众听的方法，包括"哪些东西**不能**给人看"

这套方法在这门课里用关系数据库练一次，以后你碰到很多类似的小 repo 都是同一个流程。


## 这个 repo 装了什么

`examples/` 目录下五个编号脚本，对应关系数据库 CRUD 的四个动词：

```
examples/
├── s01_create_table.py    # CREATE TABLE
├── s02_insert_data.py     # INSERT（单条 + 批量）
├── s03_select_data.py     # SELECT（投影 / WHERE / ORDER BY / LIMIT / 四种 result 消费方式）
├── s04_update_data.py     # UPDATE（按主键 / 多行 / 计算值）
├── s05_delete_data.py     # DELETE（按主键 / 按条件 / 全删 / 对比 DROP）
└── utils.py               # print_table —— 共享 ASCII 表格打印
```

技术栈：Python 3.12 + SQLAlchemy 2.0 Core（**不是 ORM**）+ SQLite（in-memory）。
不到 800 行代码，每个脚本都自带教学注释，运行时同步打印生成的 SQL（`echo=True`）。

刻意精简到这个体量——**是为了让"学方法"压过"学内容"**。


## 五个 skill：核心动作

每个 skill 是一个 Claude Code slash command，进入 Claude Code 后直接输入命令名即可。它们不是文档，是**互动式的对话流程**——AI 主动引导，你回答问题，跟人面对面学一样。

### 1. `/learn-this-project-absorb` —— 吃透

带你从"刚打开这个 repo"走到"每个文件、每行、每个设计选择都能讲出 *是什么 + 为什么*"。

进去之后 AI 会让你三选一：(a) 端到端把项目跑一遍、(b) 从架构 top-down 讲、(c) 选某个具体模块深挖。它会一边讲一边逐个组件提问检查你是否真的理解 WHY——讲三句话不提问就违规。**这是学一个项目时第一个该用的 skill**。

### 2. `/learn-this-project-quiz` —— 检验

绝对不要省略这一步。**很多时候你以为自己懂了，跑两道题才发现没懂**。

进去后 AI 会让你选模式（随机 10 道、按模块、只问 WHY、难度递进），然后一题一题问你。每题答完打分（✅/⚠️/❌），错了告诉你正确答案和源文件位置。题库目前 67 题，覆盖配置/引擎/CRUD 各种细节和设计 WHY。

absorb 学完用 quiz 校准——这是从"自我感觉良好"到"真懂"的桥。

### 3. `/learn-this-project-elevate` —— 拔高

absorb 讲的是"项目里有什么"。elevate 讲的是"项目里**没有**但应该有什么"，以及"要把这些做出来你得先学什么"。

进去后 AI 会先给你一个优先级清单（这个 repo 优先该补的：测试、README、ORM 版、多表 JOIN……），你挑一个方向，AI 就带你过四步：现状 → senior 工程师版本应该长什么样 → 还有哪些替代方案、各自的取舍 → 要做这件事你需要的前置知识 + 学习路径。

如果你说"我前置知识也不会"——AI 会进入家教模式直接教你那个前置知识。**这是把"知道我不知道什么"变成"知道我该去学什么"的工具。**

### 4. `/learn-this-project-interview` —— 应对

模拟一个真实的面试官。**不是出题机**——是会反问、会 push back 的那种。

开场会先问你 3-4 个问题校准（目标岗位/级别、面试形式、时长、想加强或回避的方向），生成一份 interview profile 给你确认，然后才开始。五轮：你有什么 / 你会怎么拔高 / 替代方案 / 踩过什么坑 / 生产级 push back。每个回答 AI 至少 push back 一次，不许中途 coaching，反馈全部留到最后 debrief 一次性给。

适合在你打算把这个项目放进简历、或面试前的一两天用。

### 5. `/learn-this-project-demo` —— 展示

教你把这个项目讲给别人听。**不是 AI 帮你写脚本——是 AI 当教练带你练。**

进去后第一件事是问你受众是谁——如果你说"我面的是一个跟数据库无关的前端岗"，AI 会**直接劝你别 demo 这个项目**，换一个更对口的。这是诚实的建议。如果对口，AI 会给你 5 分钟版和 15 分钟版的 beat-by-beat 脚本，每个 beat 让你练一遍，AI 评点哪句话太松、哪句话太硬。最后强制走一遍"哪些东西**不能**给人看"清单（占位 README、空骨架包、scratch 目录等）——这条清单往往比脚本本身还重要。

### 知识从哪来？

这五个 skill 不是凭空生成的——它们读的是 `docs/learn-this-project/` 下面那一套分析文档（项目清单、运行手册、拔高路线图、题库、面试剧本、demo 脚本）。这些文档你也可以直接打开当书读，但**主路径是用 skill 跟 AI 对话学**，文档是后备。


## 前置课程

我们默认你已经学完：

1. **Claude Code 系列教程** —— 你能用 `/<命令>` 形式调用 Claude Code 的 slash command
2. **mise-en-place** —— 你知道这是 Mac/Codespace 上最快配好开发环境的工具

这两条任意一条不熟，请先去补。

> 这门课**不需要 AWS、不需要外部数据库、不需要任何账号**——所有代码本地跑，SQLite 是 in-memory，运行完就消失。零成本、零风险、零清理。


## 环境准备

在仓库根目录跑：

```bash
mise install
mise run inst
```

第一条装 Python 3.12 + uv，第二条装 SQLAlchemy + prettytable。

**跑不起来？** 进 Claude Code，先输入 `/learn-this-project-absorb`，跟 AI 说环境装不上、贴报错——它会带你 debug。


## 推荐学习流程

按以下顺序走，这是这门课的"主路径"：

### 第一步：用 `/learn-this-project-absorb` 吃透 + 自己跑代码

进 Claude Code，输入 `/learn-this-project-absorb`，按 AI 引导一个组件一个组件走。

**关键：每讲完一个脚本，自己亲手把它跑一遍。**

```bash
uv run python examples/s01_create_table.py
uv run python examples/s02_insert_data.py
# …一直到 s05
```

看终端打印的 SQL 和 ASCII 表格，对照 AI 解释。看到不懂的输出，截图丢给 AI 问。**只看不跑等于没学。**

### 第二步：用 `/learn-this-project-quiz` 检验

跑完一两个脚本就来一轮 quiz。**别等到全学完才测**——绝大多数知识盲点是在你"以为懂了"的地方。

第一次随机 10 道，看哪些标签错得多（比如 SELECT 错了 3 道）→ 回到对应脚本重学 → 再来一轮。

**直到一轮 quiz 80% 以上正确，再进入下一步。**

### 第三步：用 `/learn-this-project-elevate` 拔高

absorb + quiz 让你"会了项目里的东西"。elevate 让你看到**项目外面**——这个项目下一步该怎么进化、senior 工程师会做什么、做这些要学什么。

挑你最感兴趣的一两个方向走完。这一步会大量产生"我下一个想学的小项目"——把那些记下来，就是你的下一阶段学习路线图。

### 第四步：用 `/learn-this-project-interview` 挑战自己

绷紧神经，被人问。

如果你打算把这个项目放进简历或面试谈，这一步必跑。AI 会比 quiz 严苛得多——它要的不是你知道答案，而是你能在 push back 之下站住。debrief 时会告诉你哪三道题该回去再准备一次。

### 第五步：用 `/learn-this-project-demo` 学怎么展示

最后这一步是为了"把它讲给别人听"。即使你不打算 demo 给别人，也值得跑一遍——因为它会强制你走"哪些不能给人看"清单，让你对自己 repo 的边界有清醒认识。


## Mentor's Note

> 这一节是我作为导师想跟你讲的话——比技术细节更重要。

**这门课你真正该带走的，不是 SQL，是这五个动作的肌肉记忆。**

我用关系数据库做载体，是因为它够简单——你不会被技术细节淹没，注意力可以放在"我现在在用哪个 skill、为什么用这个"。但你以后会接到几十、几百个类似的小 repo——一个新的 ORM、一个新的 message queue、一个新的鉴权库——每个都该用同样这五个动作走一遍。

很多人学一个新东西的方式是：从头读到尾、然后跳出去做项目，结果中间漏一大块自己没意识到的盲点。**absorb + quiz + elevate + interview + demo 这五步是为了堵住那个盲点**——absorb 让你不漏，quiz 让你诚实面对漏的部分，elevate 让你看到自己的天花板，interview 让你扛住外部检验，demo 让你能输出。

第二个想说的：**对自己诚实**。quiz 答错了就是错了，AI 不会骂你，但你也别欺骗自己说"我其实知道，只是没说清"。每次错都是一次小升级的机会，错得越早越便宜。

第三个：**不要孤立用一个 skill**。absorb 不配 quiz 是空学，quiz 不配 elevate 没有上限，interview 不配 demo 是闭门造车。五个一起用，效果远大于五个加起来。


## 展示你的学习成果

🚨 **重要：请认真读这一节，这是你的 actionable item！** 🚨

学完之后，把你的学习过程展示在 GitHub 上，让别人看到你是一个会拆问题、循序渐进、持续学习的人。

### 创建你自己的仓库

本教程仓库是 private 的。你需要：

1. 把本项目下载到本地
2. 创建一个**新的 public 仓库**

仓库命名建议：不要照搬 `learn_relational_database_basic_in_sqlite`。加上你自己的名字、去掉 `learn`、加 `POC`。例如：

```
firstname-lastname-relational-database-basic-poc
```

也可以自己起个性化名字，不要跟同学撞车。

### 分步提交（非常重要）

🚨 **不要把所有文件一股脑塞进一个 commit！** 🚨

把它当成一个**渐进式学习过程**展示。建议：

1. 先提交根目录下的配置文件（`mise.toml`、`pyproject.toml`、`.gitignore` 等）
2. 再提交 `learn_this_project/` 包骨架
3. `examples/` 里的脚本**一个一个提交**——`utils.py` 一个 commit，`s01` 一个 commit，`s02` 一个 commit，依此类推

总共至少 **10-15 个 commit**，呈现"我一步一步在学"的过程，而不是"我把答案抄完了"的过程。

### 🚨 必须删除的文件 🚨

在你的新仓库中，**请务必删除以下内容**：

- `README.md`
- `README-cn.md`（这一份，对，就是你正在读的这份）
- `docs/learn-this-project/`（整个文件夹）
- `.claude/skills/learn-this-project-absorb/`、`learn-this-project-elevate/`、`learn-this-project-quiz/`、`learn-this-project-interview/`、`learn-this-project-demo/`（5 个生成出来的 skill 目录）

这些是**教学产物**，不是你"自己学出来"的东西。留着别人一眼看穿就是抄的。

### 自己写一份 README

删完之后，你的项目就只剩源码了。这时候**自己写一份 README**——讲一句话这个项目是什么、怎么跑、你在里面学到了什么。不长，三五段就够。这才是一个看起来像"我自己探索学的"的项目。

### 最终效果

你的 public 仓库应该看起来像：

- 10-15+ 个渐进式 commit
- 一份你**自己写的**简洁 README
- 没有任何教程痕迹（没有 README-cn.md、没有 `docs/learn-this-project/`、没有生成的 5 个 skill 目录）
- 让看的人觉得：这个人会拆小问题、会一步步学、会自己输出

这是这门课最终的"产品"——不是 5 个 SQL 脚本，是这个 repo 体现出来的你。
