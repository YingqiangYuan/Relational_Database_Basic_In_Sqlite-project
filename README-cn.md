# 怎么吃透一个小型学习 repo（以关系数据库为例）

> 这份 README 请你慢慢读。它故意写得很长——本课程真正的产品是这套方法论本身，你之后还会在几十个类似的 repo 上反复使用它。

## 第一部分：这门课到底在讲什么

### 这不是一门关系数据库教程

先把调子定准：**这门课不是讲"关系数据库"的**。SQL 只是载体——它足够小，让你在零计算机背景（前提是你完成了本系列之前那门"用 AI 学习"的前置课）也能跟上；又足够完整，能把一整套学习方法跑下来。你真正来这门课学的，是**一套可复用的、AI 辅助的方法——拿到任何一个"技能尺度"的小 repo，怎样把它彻底吃透**。

这个区分很关键。如果你学完后只记得 `select(users_table).where(...)`，那你只拿到 10% 的价值；如果你学完之后带走的是一套"五步法"——下一次拿到一个小 repo（一个消息队列库、一个鉴权库、一个 embedding 模型的 client、一个新框架、一个垂直领域的小项目）就能直接套上去——那你拿到的是另外那 90%。

### "项目级"工作 vs "技能级"小项目

你的职业生涯里会有两类工作：

- **项目级工作** —— 真正在交付东西。一个后端、一个数据看板、一条数据管道、一个功能。复杂、跨越数月、交付的是整套系统，整个项目里又包含几十个更小的子问题。
- **技能级小项目** —— 你在做大项目时，碰到一个不熟的子问题（一个新的 ORM、一个消息队列、一种特定的鉴权流程），正确的动作是**把那一小块单独拎出来**，做一个最小可运行的独立 repo，专门把那一件事学透，然后再把它接回大系统里。

你现在读的这门课就是**第二类**的范例。真正的交付物是上面那个"把它拎出来学透"的动作本身。关系数据库只是这个特定小项目恰好教的话题。

### 为什么这事重要：未来你会遇到几百个这样的项目

这里有一个很多学生一开始低估的事实：**未来几年你的职业生涯里，会源源不断地冒出"技能级小项目"**。每一个新框架、每一个新数据库、每一个新 SDK、每一个新的垂直领域技能（某种 LLM 评测方法、某种统计方法、某种 UI 模式）都值得用一个小 repo 单独走一遍。

如果你每个都用"非结构化跟教程 + Stack Overflow 搜 + 自我感觉良好地挥手而过"的方式来学，每个要花一周。如果你每个都用同样这五步法、**两天专注**就能吃透，那你的速度就快了好多倍。乘上一整个职业生涯，差距巨大。

我们之所以认真做**第一个**这种小项目（也就是这个关系数据库 repo），就是为了让你把这套动作内化下来。第二个会快一点；第十个会变成自动化反应。**那种自动化反应才是这门课真正要给你的能力。**

### 五步法（先一句话各讲一下，下面会展开）

- **吃透**（Absorb）—— repo 里**有**的东西，全部弄清是什么、为什么这么写。**先做、再理解 How、再理解 Why**。
- **检验**（Quiz）—— 区分"以为自己懂"和"真懂"，是一个**下限保障**，同时也是一种问答交互模式。
- **拔高**（Elevate）—— repo 里**没有**但应该有的东西，以及你要做这些升级需要的前置知识。
- **应对**（Interview）—— 模拟面试官给你 push back，把整个项目当作你自己的作品来答。
- **展示**（Demo）—— 怎么把这个项目讲给别人听——以及哪些东西**不能**给人看。

下面的内容会展开每一步、讲清楚走的顺序——更重要的是，讲清楚**怎么用它们才对**，而不是把每一个 skill 当成"打开来从头跟到尾"。


## 第二部分：这个 repo 里装了什么（具体例子）

教学内容在 `examples/` 目录下，由**两个平行的五脚本系列**加一个共享工具和一个引导 README 组成：

```
examples/
├── README.md                 # 背景：为什么用脚本、为什么 SQLite、为什么 SQLAlchemy、
│                               以及阅读顺序——先读这一个
├── s11_create_table.py       # 原生 SQL（text）：CREATE TABLE
├── s12_insert_data.py        # 原生 SQL：INSERT（单条 + 批量，:name 参数绑定）
├── s13_select_data.py        # 原生 SQL：SELECT（all / 投影 / WHERE / ORDER / 消费方式）
├── s14_update_data.py        # 原生 SQL：UPDATE（按主键 / 多行 / age = age + 1）
├── s15_delete_data.py        # 原生 SQL：DELETE（按主键 / WHERE / 全删 + DELETE vs DROP）
├── s21_create_table.py       # Core Expression：同一节课，MetaData + Table
├── s22_insert_data.py        # Core：insert(t).values(...) + executemany
├── s23_select_data.py        # Core：select(t).where(...).order_by(...).limit(...)
├── s24_update_data.py        # Core：update(t).where(...).values(...)
├── s25_delete_data.py        # Core：delete(t).where(...)
└── utils.py                  # print_table —— 两个系列共用的 ASCII 表格打印
```

技术栈：Python 3.12 + SQLAlchemy 2.0（先用 `text(...)` 写原生 SQL，再用 Core Expression——**故意不用 ORM**）+ SQLite in-memory。代码量大约 1000 行以内。每个脚本都有大量教学注释，一条命令就能从头跑到尾。

代码量**故意做得很小**。如果是 50 个文件的业务逻辑，你会把全部时间花在"学这个代码"上，反而没空学方法。方法论一定要压过内容。


## 第三部分：五个核心动作（这门课的灵魂）

五个动作分别对应一个 Claude Code 的 slash command —— `/learn-this-project-<名字>` 的形式。每个 skill 加载一小段提示，引导你进入一段对话式的学习流程。**重点：它们不是聊天机器人，也不是"带按钮的文档"。把每一个 skill 想成是一位精通这个 repo 的导师的某一种特定"指导模式"**——你问不同种类的问题，导师会进入不同的模式来回应你。

下面逐个详细讲。**五个全部读完再去运行任何一个**——你需要先在脑子里有它们如何配合的整体模型。

### 1. `/learn-this-project-absorb` —— 吃透

> 这个 skill 的底层逻辑：*这个项目的原作者（也就是你的导师）已经把你需要知道的一切，写成了一套分析文档放在 `docs/learn-this-project/` 下面。AI 把这些文档建立了索引。Absorb 这个 skill 按照一个合理的顺序，一步一步带你走一遍导师准备好的内容。*

它要让你做的概念动作很清晰：**先做、再理解 How（怎么工作的）、再理解 Why（为什么这么做）**。就是这个顺序。

- **先做（Act）** —— 你把脚本跑起来，看输出。不要急着理解任何东西，你要的就是先把**这段代码跑起来会发生什么**亲眼看一遍。这一步刻意是**非创造性的**，你不需要创新，跟着走一遍就好。
- **How** —— 现在回到每个脚本，跟 AI 一起把每一行做的事情机械地走一遍。`engine.begin()` 到底返回的是什么？`inspect(engine)` 在看什么？`text(...)` 包了个什么？How 这一层的问题靠和 AI 一起读代码来回答。
- **Why** —— 当你能讲清楚代码**做了什么**，再去问**为什么是这么写而不是那么写**。为什么先教原生 SQL，再教 Core？为什么用 `:memory:` 而不是文件？为什么每个脚本都要重新声明 schema？这一层是你从"复制粘贴侠"变成"自己能做设计决策的人"的分水岭。

Absorb 是新项目要用的**第一个** skill，永远是。但是——这里很多人没意识到——**Absorb 不是一个"坐在那里让 AI 把你从头拖到尾"的东西**。怎么*正确地*使用它，第六部分（推荐学习路径）会详细讲。这里你只需要记住：它给你高层次的地图，再给你一堆"为什么"的问题，让你之后回来问。

### 2. `/learn-this-project-quiz` —— 检验

导师预先写了一套题库——大约 30–60 道经过精心设计的题目，覆盖这个 repo 中一个认真的学习者应该内化的所有重要部分。Quiz skill 把题一道一道抛给你，你用自己的话作答，AI 拿你的答案对照标准答案给评分。

**Quiz 是一个下限保障，不是一个上限测试。** 你把所有题答对，只能说明你"踩到了导师认为人人都该知道的那条底线"，不能说明你已经"精通这个 repo"。任何预先写好的题库都圈不住"精通"的边界。所以你看 Quiz 分数时，要把它读成"我有没有踩到底线？"，而不是"我在这个话题上是不是 10 分？"。

Quiz 还有一个**第二种用法**，是大多数学生没意识到的：**Quiz skill 本质上是一套"问答交互模式"**。你把题库刷完之后，你可以**让 skill 自己生成新题**——"围绕参数绑定，再给我出五道更难的题"，"专门测我对 `lastrowid` 和 `inserted_primary_key` 区别的理解"——题库可以是预制的，也可以是你自己定义话题让它现生。这种第二种模式，Quiz 就从一个"背答案"工具变成了一个"思维训练"工具。

### 3. `/learn-this-project-elevate` —— 拔高

Absorb 讲的是 repo 里**有**的东西。Elevate 讲的是 repo 里**没有**但应该有的东西——以及你要把这些做出来需要先学什么。

针对这个 repo，拔高路线图覆盖的方向包括：给两个脚本系列加一个真正的测试套件、再加一个第三系列（`s31`–`s35`）教 ORM、加多表 + 外键来教 JOIN、用 logging 替换 `echo=True`，等等。每一个升级方向都会给你（a）现状、（b）senior 工程师版本应该长什么样、（c）替代方案及其取舍、（d）做这个升级所需的前置知识。

这里关键的概念动作是：**纯概念理解是不够的**。如果你只是把"拔高"作为一个讨论（"嗯我会加测试，大概这么加"），你只吃下大概 30%。如果你**把这个拔高真的在这个 repo 上动手做出来**，你能吃下 90%。所以 Elevate 这个 skill 天然要和 Absorb 配对成一个反馈循环：

1. 用 **Elevate** 找出你真正在意的一个拔高方向，搞懂"做好长什么样"，并学到所需的前置知识。
2. 把其中一个拔高目标当作一个具体的交付物（"我要加一个 tests/ 目录，对每个脚本做 smoke test，断言关键标题打印出现"）。
3. **切回 Absorb**，带着这个目标进去。告诉它："针对这个拔高目标，带我走一遍现有代码里我需要碰的部分，然后帮我在现有结构上把它建出来"。Absorb 这时的角色就变了——它不再是讲解现有代码，而是帮你*做*拔高动作。

**这种 Elevate → Absorb 的循环，是这门课里最有价值的一个动作**。比再读更多教程快得多。

记住：你不一定真要把这个拔高发布上线。重点是**试着做**——花一两天真的动手建一部分。肌肉记忆就是在这里形成的。

### 4. `/learn-this-project-interview` —— 应对

Quiz 用的是一个固定模板：一道具体的题，一份具体的答案，对着一份具体的评分标准。有用，但是有边界。

Interview 比 Quiz 开放得多。**你把整个项目当作你自己的作品**，skill 扮演一个尖锐的面试官，在压力下追问你的理解。五轮：你有什么 / 你会怎么拔高 / 替代方案 / 踩过的坑 / 生产级 push back。每个回答 AI 至少 push back 一次，不许中途 coaching，反馈全部留到最后 debrief 一次给完。

Interview 适合用在你**真的想检验自己**到"能不能在陌生人面前撑住"这个层级的时候——比如把这个项目放进简历之前、真实面试前一两天、或者就单纯想看看你能不能扛住质疑。这是表面级理解被照见的地方。

### 5. `/learn-this-project-demo` —— 展示

这是大多数学生**最被低估**的一个 skill，但同时它的职业杠杆**最高**。

Demo 是为这个场景设计的：在面试中、在电话里、在和同事的对话里，对方问你"*你会不会 X？*"——X 是某种技能。证明你会 X 最有力的方式，**不是**回答"我会"加上一段口头描述；**而是当场打开你学这个技能时做的那个项目，带对方实地走一遍**。

而那个项目，就是这个 repo（更广泛地讲，就是你下一个 learn-this-project repo、再下一个，等等）。Demo skill 教你**如何在不同受众条件下有效地展示这个项目**——怎么挑入口、怎么排"亮点"出现的顺序、跳过哪些、绝对不能给人看哪些。很多学生其实做了好工作，但讲不清楚——内容是有的，框架感不够。Demo 就是把这个框架感补上。

一个重要的副产品：Demo skill 里那张"**绝对不要展示的清单**"（占位 README、scratch 目录、半成品功能等）会**逼你正视**"我这个 repo 里哪些东西能给别人看，哪些会让我显得 junior"的边界。跑一次 demo skill，你对自己 repo 卫生状况的认识会比读十遍代码评审清单还要深。


## 第四部分：两类知识，以及 skill 在中间扮演什么角色

在你运行任何 skill 之前，你要先理解 **skill 在底层到底在做什么**。这里只给一个简要的框架，下一门课会展开。

任何一个这种项目里，其实有**两种知识**：

1. **工作本身。** `examples/` 里的代码、`pyproject.toml` / `mise.toml` 里的配置、数据、设计选择——这些**就是项目**。是你来这里学的内容，是你如果在真实工作中做这个题目所要动手的东西。
2. **导师对工作的 notes。** `docs/learn-this-project/` 下面那一套分析文档——组件清单、运行手册、拔高路线图、题库、面试剧本、demo 剧本。这些**不是项目内容**，是导师写的"这个项目应该怎么教、怎么学"的注释。当索引用。

`.claude/skills/learn-this-project-*/` 下面的五个 skill，**先去读导师的 notes**，再根据 notes 指向哪里去访问项目本身的内容，然后帮你把它消化下来。skill **不是"打开来从头到尾读"的一本书**，它们是"你需要帮助时进入的一种指导模式"。

这意味着：

- **当你不知道下一步怎么走时，skill 价值最高。** 刚 clone 完 repo、还没有地图——Absorb 的全局梳理这时最值钱。探索某个具体文件时撞墙——切回 skill 让它把你重新定位。要去 demo 之前——Demo 给你一个结构。
- **当你正在做事且知道自己在做什么时，skill 价值最低。** 真正在跑脚本、在带着目的读代码时，你不需要"指导模式"，你需要**自己在做事**。不要为了每一行代码都把 AI 拽进来对话——你学得反而更慢。
- **真正的"主路径"是你在做事、agent 在你需要时帮忙**——不是"我打开 Absorb 从头跟到尾"。第六部分会把这件事讲到具体的可操作层级。

（关于 skill 底层到底在做什么的更深一层——包括 meta-skill 一开始是怎么生成这些分析文档的、以及如何为自己将来的 repo 做同样的事——会在后续课程里展开。这里你先记住上面这个模型就够了。）


## 第五部分：前置课程和环境准备

我们默认你已经完成：

1. **Claude Code 系列教程** —— 你能用 `/<命令>` 形式调用 Claude Code 的 slash command，也能看懂它的输出。
2. **mise-en-place** —— 你至少用 `mise` 配过一次开发环境。

任意一条不熟，请先去把那一门补完——否则下面这些步骤会一路给你制造麻烦。

> 这门课**全部在你本地机器上跑**。不需要外部数据库，不需要任何云端账号，不需要注册任何服务。SQLite 是 in-memory 的——每个脚本启动时建库、退出时销毁。**零成本、零风险、零清理。**

### 一次性环境准备

在仓库根目录跑：

```bash
mise install               # 装 mise.toml 里 pin 住的 Python 3.12 和 uv
mise run venv-create       # 创建 .venv/（== uv venv）
mise run inst              # 装依赖（== uv sync --all-extras）
```

完成了——你现在可以跑任何一个示例脚本：

```bash
uv run python examples/s11_create_table.py
```

如果某一步出问题，恢复动作和这门课其它部分一样：打开 Claude Code、运行 `/learn-this-project-absorb`、贴报错给它、让 AI 带你 debug。


## 第六部分：推荐学习路径（请认真读这一节）

**这是整份 README 最重要的一节。** 大多数学生使用这五个 skill 的方式是把每个 skill 都当成一个"打开 → 从头到尾跟一遍 → 关掉"的线性任务。**这不是正确的用法**，而且效果很浅。

正确的心理模型：**这五个 skill 是一个对这个 repo 了如指掌的专家导师，使用导师和使用教科书的方法是不一样的**。你迷路时找导师要方向，你被卡住时找导师问具体问题。你不会要求导师"把所有他想说的话从头一句一句念给我听"。

下面是**推荐顺序**，并且会明确告诉你**每一个 skill 怎么用才对**。

### 第一步：Absorb，三段式（这一步比看上去要细）

#### 阶段 1A：拿到全局地图

打开 Claude Code，运行 `/learn-this-project-absorb`。让它**只**带你过**高层次的地图**：`examples/` 里有什么、为什么是 s1x + s2x 两个平行系列、`utils.py` 干啥的、空的 `learn_this_project/` package 是干啥的。**先不要深入任何单一文件**。这一阶段的目标就是一件事——**离开时你脑子里要有这个 repo 的目录，并且要清楚知道哪些文件你需要"读"、哪些文件你需要"跑"**。

这个区分非常关键，skill 应该帮你画出来。在这个 repo 里：

- 该**读**的文件：每个脚本的 docstring、`examples/README.md`、`utils.py`。这些不是用来跑的，是用来当散文读的。
- 该**跑**的文件：十个编号的脚本。这些**不是只读**——你要真的输入 `uv run python examples/sNN_*.py` 然后看输出。不跑就没学会，只算扫一眼。

如果第一次 absorb 跑完你还说不清这个区分——你就漏掉了阶段 1A 的核心目标，再问 skill 一次。

#### 阶段 1B：离开 skill，自己探索

把 Absorb 那个对话关掉。打开一个**新的** AI 对话（或者干脆不开 AI）然后开始**做事**。读标了"读"的文件。跑标了"跑"的文件。盯着输出看。发现一些自己注意到的细节。形成你自己的问题。**这一阶段不可省略。** 跳过这步等于把整个学习外包给了 agent——会话窗口关掉的瞬间，你脑子里啥也没剩。

当你停在某个具体的位置——"等等，`result.lastrowid` 到底干啥的？跟 `inserted_primary_key` 有什么不同？"——这就是阶段 1C 该上场的信号。

#### 阶段 1C：再开 skill，带 context 进去

这时**再次**打开 `/learn-this-project-absorb`，但这一次告诉它**你现在在哪儿、在干啥**："我在 `s12_insert_data.py` 大约 80 行，我想搞明白 `result.lastrowid` 是干啥的、它和 s22 里 Core 那边的对应物有啥关系"。skill 现在真正派上用场——你给了它具体上下文，它可以**针对这个上下文**深入地帮你拆解，而不是再把整个 tour 给你拖一遍。

阶段 1C 的第二个用法：**你卡住了不知道下一步该干啥**。打开 skill 跟它说"我刚走完 SELECT 那几节，不太确定接下来该重点搞什么。考虑到我两周后要 demo 这个项目，你建议我下一步做什么？"——skill 可以帮你规划下一步。

阶段 1C 的第三个用法（这是它真正威力的所在）：**当你想做一些课程没覆盖的事情**——加一个小扩展、改动一个脚本来测试你的某个假设、走一条课程里没走的路。skill 脑子里有整个项目的全图，可以告诉你该动哪些文件、考虑哪些设计选择。**把它当一个全知全能的项目专家**，不要当成"一份教程的朗读者"。

### 第二步：Quiz，两种模式

阶段 1B 至少跑完前几个脚本之后，跑一轮 Quiz。

**模式 A：预制题库。** 让 skill 随机抛 5–10 道题。**诚实地给自己打分**——你答错的那道题，**答案没浮在你的舌尖上，那就是你在帮自己掩盖**。这里的每一个错都是金矿——每一个错都指出你模型里的一个洞，回到对应文件花两分钟就能补上。

**模式 B：开放式。** 一旦你刷完题库的底线，**直接让 skill 出新题**："专门围绕参数绑定的安全含义，再给我出五道更难的题"。这时你在使用 skill 的 **Q&A 行为**而不是它的题库内容。Quiz 在这种用法下，是一个思维训练工具。

不断在第一步（absorb + 自己探索）和第二步（quiz 两种模式）之间循环，直到你能回答**任何题库里都没有但你能想象一个有经验的工程师会问**的那类题——"如果这张表有 5000 万行，这个设计在哪里会崩？"，"`engine.begin()` 里我 raise 异常然后在更外层 catch，它到底会怎么处理？"。

### 第三步：Elevate（以及 Elevate-Absorb 循环）

当你能把现状部分讲明白了，跑 `/learn-this-project-elevate`。挑一两个**你真正感兴趣**的拔高方向——不要挑最长的清单，也不要挑听起来最厉害的，要挑那种**让你眼睛发亮**的。skill 会带你走"现状 → senior 目标 → 替代方案 → 前置知识"四步。

然后——**这一步大多数人停下来，请你不要停**——把其中一个拔高方向落实成一个具体目标（"我要加一个最小的 `tests/` 目录，对两个脚本系列分别做 smoke test"）然后**切回 Absorb**，带着这个目标进去。Absorb 这时的角色从"讲解现有代码"变成"帮我在现有代码之上建一些新东西"。

**这个 Elevate → Absorb 循环，是这门课最有价值的一个循环**。概念理解是一个层级，亲手扩展是上面两个层级。

你不需要真的发布这个拔高升级。**重点是动手试**——花一两天真的把它的一部分建出来。肌肉记忆就在这里形成。

### 第四步：Interview

至少做过一次 elevate 之后，跑 `/learn-this-project-interview`。这是**完整性检验**。skill 会全方位检验你的理解，并且 push back。**认真对待**——它问"为什么不用 Postgres"，你答了之后它会追问"你刚才说 SQLite 有方言坑，**举一个**会真的误导初学者的"。如果你答不上来，说明你其实还没真的理解这个取舍。回去补，再跑一遍。

把 Interview 当作"决定你要不要把这个项目放进简历"或"决定你能不能拿这个项目去和真人讨论"的关口。

### 第五步：Demo

最后一步。跑 `/learn-this-project-demo`，告诉它你想象的受众是谁（**要具体**——"一个数据工程岗的招聘经理，公司规模小"），让 skill 带你过一遍推荐展示流程 + **强制走一遍**"绝对不要展示"清单。最后这张清单是大多数人跳过、但又最需要的——它是"打磨过的 demo"和"无意中暴露我是 intermediate 工程师的 demo"之间的差别。

走完 Demo 你就完成了这套五步法的一个完整循环。下一个 repo 会更快。


## 第七部分：展示你的学习成果（长线杠杆）

**这一节是整份 README 杠杆最长的一节，请认真读。**

### 这件事为什么重要

每一个你完成的 learn-this-project repo，都是一个**可以放上简历的作品**。**不是**我们给你的这个原始教程 repo——这一个是教学产物，不应该作为你对外展示的工作；**而是**你自己开的一个**全新的 public 仓库**，你在里面**一段一段、一个 commit 一个 commit**地把项目的内容重新建出来，让 GitHub 历史读起来像"我一步一步把这个题目搞明白了"。

这件事重要有三个原因：

1. **面试中，当对方问你会不会某个技能，最强的证明方式是当场打开你学这个技能时做的那个项目，带对方走一遍**。一句"会"加一段含糊描述是弱信号；现场带人走过一个干净、分阶段提交、清清楚楚的 repo，是压倒性的强信号。
2. **你完成多个不同技能的 learn-this-project repo 之后，这套合集就是你这个人的"知识图谱"**——一个关系数据库 POC、一个 LLM 评测 POC、一个消息队列 POC、一个特定统计方法的 POC。从这套合集里，别人能看到你的成长轨迹、你的覆盖面。比一份简历的技能 bullet 列表强得多。
3. **你在这个过程里学会的"把工作打磨成一个可展示的作品"的动作本身就是一项技能。** 很多工程师做了好工作但拿不出手——分阶段提交、亲手写一份 README、把教学痕迹清干净——这些动作本身就是一种练习，你只能通过反复做来掌握。

### 最重要的一条铁律：不要被识破是教学项目

你的观众**绝对不能**看出来这是从一个教程里搬出来的。如果他们能看出，你这个 demo 的说服力会**从"这个人学会了一个硬技能"翻转成"这个人跑了一个教程"**——这在面试中是**负信号**，不是正信号。

这意味着所有**长得像教学产物的东西**都必须从你的 public 版本里删干净：

- 教学型 README 文件（`README.md`、`README-cn.md`——也就是你正在读的这一份）。
- 导师写的那一套分析文档 `docs/learn-this-project/`。
- 教程归档 `docs/tutorials/`（如果存在）。
- 五个生成出来的 skill：`.claude/skills/learn-this-project-{absorb,quiz,elevate,interview,demo}/`。

你的 repo 越像一个**真实的、第一人称的、自己探索出来的项目**，信号越强。**这些知识必须存在你脑子里、存在你亲手写的 README 里、存在你带观众走代码的方式里**——不能存在那些一眼就指回教程的产物里。

### 分步技术细节

#### 第 1 步：clone，不 fork

把项目拉到本地。**不要在 GitHub 上 fork** 教程 repo——fork 会留下指回教程的链接，整个"这是我自己的项目"的设定就破了。

```bash
git clone <教程-repo-url> firstname-lastname-relational-database-basic-poc
cd firstname-lastname-relational-database-basic-poc
rm -rf .git
git init
```

#### 第 2 步：在 GitHub 上开一个**新的** public repo

仓库名要**有你自己的辨识度**——别照搬教程的名字。常用的模式：

```
firstname-lastname-<主题>-poc
```

比如：`jane-doe-relational-database-basic-poc`。挑一个个性化的、不要跟同学撞车、不要呼应教程标题。

#### 第 3 步：**第一次 commit 之前**就把教学产物删干净

第一件事，在你 stage 任何东西之前，把所有教程加的东西删掉：

```bash
rm README.md README-cn.md README-ORIGINAL.md
rm -rf docs/learn-this-project/
rm -rf docs/tutorials/                          # 如果有的话
rm -rf .claude/skills/learn-this-project-absorb/
rm -rf .claude/skills/learn-this-project-quiz/
rm -rf .claude/skills/learn-this-project-elevate/
rm -rf .claude/skills/learn-this-project-interview/
rm -rf .claude/skills/learn-this-project-demo/
```

你**可以保留** `.claude/skills/learn-this-project-meta/`——这个 meta-skill 是真值得你以后在自己项目上反复使用的能力。它是加分项，不是露馅项。

#### 第 4 步：分阶段提交——至少 10–15 个 commit

**这一步对 repo "看起来怎样"贡献最大**。一个浏览你 commit 历史的人，应该能看到一个**故事**在展开：

| 阶段 | Commit（大致）                                                                       |
| :--- | :----------------------------------------------------------------------------------- |
| 1    | "Initial mise + uv toolchain setup（`mise.toml`、`pyproject.toml`、`.gitignore`）"   |
| 2    | "Add empty `learn_this_project/` package skeleton"                                   |
| 3    | "Add `examples/utils.py` —— 共享 ASCII 表格渲染"                                       |
| 4    | "Add `examples/README.md` —— 课程引导"                                                 |
| 5    | "Add `s11_create_table.py` —— 用原生 SQL 写 CREATE TABLE"                              |
| 6    | "Add `s12_insert_data.py` —— INSERT，引入参数绑定"                                     |
| 7    | "Add `s13_select_data.py` —— SELECT 系列（WHERE、ORDER、消费方式）"                    |
| 8    | "Add `s14_update_data.py` —— UPDATE 模式与 `rowcount` 检查"                            |
| 9    | "Add `s15_delete_data.py` —— DELETE 与 DELETE-vs-DROP"                                |
| 10   | "Add `s21_create_table.py` —— 同一节课的 SQLAlchemy Core 版本"                         |
| 11–14| "Add s22 / s23 / s24 / s25 —— Core Expression 版本"                                   |
| 15   | "Write `README.md` 总结项目与我学到的东西"                                              |

**尽量分散到几天内提交**——commit 日期带有"我用了几天认真做"的暗示。**绝对不要忍不住把多个脚本塞进同一个 commit**。每一个脚本都是这节课的一块，让每一块有自己的 commit。

Commit message 用**你自己的语气**写，**过去时**，就像你在加这个文件那天写下的。"Add `s13_select_data.py`" 够用；"Add `s13_select_data.py`，因为……" 更好。

#### 第 5 步：自己写一份 README

教学产物删完、commit 也分好了，现在**用你自己的语气**写一份新的 `README.md`。三到五段足够：

- 一段：这个项目是什么、覆盖了什么。
- 一段：怎么装、怎么跑。
- 一段：你建这个项目带走了什么——**用第一人称反思的语气**，不要变成"教程总结"。
- 可选：一段写你下一步会加什么（用你自己的话写你的拔高目标）。

确保整份 README 读起来**像*你*写的**。如果你写出来读起来像教程摘要，重写一遍，写得更口语化一点。

### "做完了"长什么样

你的 public 仓库最后应该看起来：

- 10–15+ 个分阶段的 commit，用第一人称语气的 message，散布在几天里。
- 一份**你自己写的**简短 README。
- 零教学痕迹：没有 `README-cn.md`、没有 `docs/learn-this-project/`、没有 `.claude/skills/learn-this-project-{absorb,quiz,elevate,interview,demo}/`。
- `mise.toml` + `pyproject.toml` 真的能跑（别人 clone 之后能 `mise install && mise run inst && uv run python examples/s11_create_table.py` 然后成功）。
- 你能**当场带人走一遍**的代码——意味着你真的读过每一行，不是抄过去就完事了。

那种综合信号——"这个人会拆问题、会一步一步推进、能产出东西"——就是这门课真正的产品。


## 第八部分：导师的话

> 你的导师跟你说几句——慢慢读，比技术细节更重要。

**你真正带走的，不是 SQL。** 是这五个动作的肌肉记忆，是把它们当成一个**系统**而不是"五个独立的脚本"去使用的纪律。

我选关系数据库做这门课的载体，是因为这个话题简单到不会让你被框架细节淹死。这就把你的注意力释放出来留给元问题——"*我现在为什么在用这个 skill？*"——而那个元问题，才是这门课真正的功课。未来几年里，你会接到几十个、上百个这样的小 repo，每个都是一个技能：一个新的 ORM、一个新的消息队列、一个鉴权库、一个 AI 客户端、一种特定的评测方法、一种特定的统计方法。每一个都值得用同样这套五步法走一遍。**当这套模式自动化了，你获取新技能的速度会比之前快一个数量级。**

大多数工程师学新技能的方式是：把一份教程从头到尾读完、做一个 toy 出来、然后跳回生产工作。结果是一个像瑞士奶酪一样到处是洞的认知模型——而你**自己看不见那些洞**。**Absorb + Quiz + Elevate + Interview + Demo 就是为了堵那些洞。** Absorb 让你不漏。Quiz 强迫你面对漏掉的部分。Elevate 让你看到天花板。Interview 用外部压力检验你。Demo 强迫你输出——这是最严苛的理解检验。

最后给你三条明确的提醒：

**对自己诚实。** quiz 跟你说你错了，那就是错了——不要骗自己说"我其实知道，只是没说清楚"。每一个诚实承认的错都是一次便宜的升级机会，你越早抓住越便宜。

**不要孤立地用一个 skill。** Absorb 不配 Quiz 是一厢情愿。Quiz 不配 Elevate 没有上限。Interview 不配 Demo 是闭门造车。这五个 skill 是复合的——五个一起跑的效果远大于五个分别跑的总和。

**不要把 skill 当成一份你要从头跟到尾的脚本。** 把它当成一个随叫随到的导师。你迷路时用它，你卡住时用它，你想做课程没覆盖的东西时用它。**学习的真正工作发生在*你*在跑代码、读文件的时候**——skill 是辅助，不是工作本身。

这套五步法是一个长期投资。你手上这门课是它的**第一次重复**。后面还有很多次。这一次走慢一点、走稳一点，下一次就会快。
